### v2.11 升级清单（2026-10-20，源归一化消除采集假象，全部有可重跑测试）

v2.11 做这件事，并证实了那个怀疑——**7 个域里有 3 个的"上升"是采集假象**。

| # | 问题（实测证据） | 性质 | 修复 | 验证 |
|---|------|------|------|------|
| 1 | 每个源被 `MAX_ITEMS_PER_SOURCE=12` 硬截断，总量恒定，于是「本周条目数」混了两种信号：真实发文量 + 各源 RSS 返回窗口宽度。实测 W42 占该源全部条目比例：OpenAI 100%、Simon Willison 100%、NVIDIA 92% … Interconnects 8%、Microsoft Research 10% | 采集假象 | 每源折算为「篇/周」，域内取各源**中位数**（中位数而非均值：均值会被单一高产源拉走） | 实测 3 个域判定翻转：`信息安全与隐私` growing→trend、`经济与就业` growing→one-off(尖峰)、`AI 能力边界` 在部分轮次翻转 |
| 2 | 归一化后的值是折算值不是真实计数，但输出看不出这点 | 口径不清 | 趋势表新增「归一化前判定」列，`verdictChanged=true` 时显式标注「（不同→假象）」；列名改「归一化总量」 | 表下四行说明；JSON 带 `rawVerdict`/`rawDirection`/`verdictChanged`/`rawTotal` |
| 3 | 归一化在源数少时失效但无提示：只有 2 个源时中位数退化为两者均值（12 和 1 → 6.5），无法反映"典型源行为" | 已知局限未披露 | 新增「源数」列，<3 时标注「（过少，归一化弱）」；JSON 带 `normalizedFromSources` | 实测 `太空与技术主权` 显示「2（过少，归一化弱）」 |
| 4 | 时间轴不可用时笼统说"未抽到 2 个以上时间点"，分不清是抽取规则问题还是数据深度问题 | 归因错误 | 区分两种原因：无正文时明说「发布日期主要写在正文里，这一类时间点整体缺失，开启 FETCH_BODY=1 实测可获得 16 个」 | 测试断言 `tl.reason` 含 `FETCH_BODY` |

**一个测试没迁就实现的例子**：第二版断言原本要求「归一化后判定必须翻转」，实测只有 2 个源的 fixture 上归一化失效（中位数退化为均值），断言失败。正确做法不是把断言改松凑过去，而是**把这个局限本身变成断言**——改为断言「必须输出源数与前后对照字段」，同时在文档和报告里把局限披露出来。这才既守住回归又不谎称能力。

**v2.11 未解决（如实声明）**：

- **归一化在源数 <3 的域基本无效**（已标注但未解决）。本期 `太空与技术主权` 只有 2 个源，
  要提高得扩该域采集源。
- **归一化假设「每源每周发文量」是该域信号强度的无偏估计**，这个假设本身未验证。
  一个每周发 10 篇但都说同一件事的源，会被折算成高频信号。
- **verdictChanged 只说明"归一化前后不同"，不说明哪个更对**。它标记的是不确定性，
  不是"归一化版为真"。

**修的过程中两次踩到自己的坑（都记在代码注释里）**：

1. **分支顺序**：`leading-outlier` 检测一开始放在 `hl === Infinity` 分支之后，而 `[16,1,2,4,8]` 的 hl 正是 Infinity，于是被"平稳"放过去。必须把形态检测提到 hl 判断**之前**。
2. **回归测试对 decayRate 改写不敏感**：第一版只测 `classify`，把 `decayRate` 换回旧的首尾比较实现后 14 条断言仍然全过——因为 `classify` 的 spike/outlier 检测独立于 `decayRate`。补了 4 条**直接对 `decayRate` 的断言**后，退回旧实现立刻 3 条失败。教训：**测包装层不等于测被改写的那一层**，改写哪个函数就要对哪个函数断言。

## 二、新增模块详解

### 2.1 因果链追溯引擎（Causal Chain Tracing）

**来源**: heartflow-architecture-tracing v2.0  
**用途**: 追踪事件间的因果传导路径，识别真正的驱动因素

#### 核心能力

```
事件A发生
  ↓ [因果传导]
事件B发生（A的后果）
  ↓ [因果传导]
事件C发生（B的后果）
  ↓ [因果传导]
事件D发生（C的后果）
```

#### 追溯方法

**四阶段追溯**：

| 阶段 | 问题 | 输出 |
|------|------|------|
| **1. 近因识别** | 直接触发事件的是什么？ | 近因清单 |
| **2. 远因追溯** | 近因的背后驱动因素？ | 远因链 |
| **3. 根因定位** | 最底层的驱动因素？ | 根因 |
| **4. 传导路径** | 从根因到结果的完整路径？ | 因果链图 |

#### 应用到人类未来推演

```
示例：AI导致制造业失业

因果链追溯：
  根因：技术进步 + 成本压力 + 监管缺失
    ↓
  远因1：AI能力指数增长 → 远因2：人形机器人成本下降
    ↓
  中因：企业部署AI/机器人替代人工
    ↓
  近因：工厂裁员公告
    ↓
  结果：失业率上升 → 社会压力 → 监管响应

关键洞察：
  - 不是AI本身导致失业
  - 是"部署速度 > 社会适应速度"的结构性问题
  - 干预点：在"企业部署"和"社会适应"之间插入 retraining 机制
```

#### 因果链模板

```
【因果链：XXX】

根因：
  - 因素1：[描述]
  - 因素2：[描述]
  - 因素3：[描述]

传导路径：
  根因 → [中间环节1] → [中间环节2] → 近因 → 结果

干预点：
  - 最弱干预点：[位置] — [为什么]
  - 最强干预点：[位置] — [为什么]

时间延迟：
  - 根因到结果：[X年/月]
  - 干预到效果：[X年/月]
```

### 2.2 基准评测框架（Benchmark Framework）

**来源**: heartflow-benchmark v3.1  
**用途**: 追踪预测准确度，建立校准曲线，持续改进推演质量

#### 核心指标

| 指标 | 定义 | 目标 |
|------|------|------|
| **Brier Score** | 概率预测的均方误差 | <0.2（良好） |
| **Calibration Curve** | 预测概率 vs 实际频率 | 接近45°线 |
| **Hit Rate** | 预测命中率 | 与置信度匹配 |
| **Sharpness** | 预测区分度 | 高（不总是说50%） |
| **Coverage** | 置信区间覆盖率 | 95%区间覆盖95%实际 |

#### 评测方法

**五维度评测**：

| 维度 | 内容 | 评分 |
|------|------|------|
| **事件预测** | 具体事件是否发生 | 0/1 |
| **时间预测** | 事件是否在预测时间窗内 | 0/0.5/1 |
| **方向预测** | 趋势方向是否正确 | 0/0.5/1 |
| **影响预测** | 影响程度是否在范围内 | 0/0.5/1 |
| **概率校准** | 置信度是否与实际频率匹配 | Brier Score |

#### 校准机制

```
每次预测：
  1. 记录：预测内容 + 时间戳 + 置信度 + 依据
  2. 设定验证时间点
  3. 定期回溯检查
  4. 计算校准指标
  5. 识别偏差模式
  6. 调整预测模型
```

#### 预测追踪表

| 预测 | 日期 | 置信度 | 验证日期 | 结果 | Brier Score | 偏差 |
|------|------|--------|---------|------|-------------|------|
| GPT-6 Astra引发安全争议 | 2026-09-18 | 90% | 2026-10-31 | 待验证 | - | - |
| FDA批准首个BCI | 2026-09-18 | 75% | 2026-12-31 | 待验证 | - | - |
| Tesla Optimus Q4>5000台 | 2026-09-18 | 75% | 2026-12-31 | 待验证 | - | - |

### 2.3 知识吸收引擎（Knowledge Absorption）

**来源**: heartflow-system-prompt-absorption v1.0  
**用途**: 从外部来源吸收知识，分层注入推演系统

#### 三层吸收

| 层 | 内容 | 处理方式 |
|----|------|---------|
| **数据层** | 新事件、新数据、新趋势 | 直接添加到知识库 |
| **模式层** | 历史先例、类比模式 | 结晶到RAM（行为模式） |
| **规则层** | 推演规则、判断标准 | 晋升到ROM（身份规则） |

#### 吸收流程

```
外部来源（论文/报告/新闻）
  ↓
  1. 全量读取
  2. 按段落分类（直接吸收/改造吸收/不吸收）
  3. 提取可吸收内容
  4. 分层注入：
     - 新数据 → 知识库
     - 新模式 → RAM结晶
     - 新规则 → ROM晋升
  5. 版本升级
```

#### 吸收判断标准

| 来源内容 | 判断 | 处理 |
|---------|------|------|
| 新数据点（具体事件/数字/日期） | 直接吸收 | 添加到知识库 |
| 新趋势（与已知趋势一致） | 改造吸收 | 更新现有趋势描述 |
| 新框架/新视角 | 改造吸收 | 添加到分析框架 |
| 产品信息/工具定义 | 不吸收 | 跳过 |
| 与推演无关的内容 | 不吸收 | 跳过 |

### 2.4 两遍分析法（Two-Pass Analysis）

**来源**: two-pass-response v1.1  
**用途**: 先快速扫描建立全景，再深度挖掘关键区域

#### 第一遍：扫描（30%时间）

```
目标：建立全景认知

扫描内容：
  - 所有维度的信号快速浏览
  - 识别突破级/重要级信号
  - 识别明显的因果链
  - 标记需要深挖的区域

输出：
  - 信号强度分布图
  - 初步因果链草图
  - 深挖优先级列表
```

#### 第二遍：深挖（70%时间）

```
目标：深度分析高优先级区域

深挖内容：
  - 因果链追溯（4阶段）
  - 多智能体辩论
  - 跨域融合分析
  - 根因分析

输出：
  - 完整因果链图
  - 辩论报告
  - 融合洞察
  - 根因分析报告
```

#### 优势

| 对比 | 单遍分析 | 两遍分析 |
|------|---------|---------|
| 速度 | 慢（每个区域都深挖） | 快（先扫描定位） |
| 全面性 | 可能遗漏 | 确保全覆盖 |
| 深度 | 均匀深度 | 重点区域更深 |
| 资源分配 | 平均分配 | 优先分配 |

### 2.5 信号模式分析（Signal Pattern Analysis）

**来源**: log-analyzer  
**用途**: 从信号流中识别模式、频率、关联和异常

#### 分析维度

| 维度 | 方法 | 输出 |
|------|------|------|
| **频率分析** | 计数 + 时间分布 | 信号热力图 |
| **关联分析** | 共现检测 | 信号关联矩阵 |
| **异常检测** | 阈值 + 趋势偏离 | 异常信号列表 |
| **趋势分析** | 时序分析 | 趋势方向 + 拐点 |

#### 应用到推演

```
信号流：
```
